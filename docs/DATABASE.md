# База данных

Сейчас приложение работает на SQLite через встроенный `node:sqlite`. Файл по умолчанию: `data/rentproof.sqlite`. Каталог `data/` не коммитится.

## Что сохраняется

Пользователи и сессии первого этапа остаются на месте. Миграция добавляет колонки `is_admin`, `blocked_at`, `plan` и таблицы объявлений, фотографий, бронирований, избранного, отзывов, отчётов AI, фиксации состояния, уведомлений, подписок, жалоб и журнала. Существующие строки не удаляются. Демонстрационные объявления добавляются только если их идентификаторов ещё нет.

Пароль демонстрационного арендодателя нигде не сохранён. Войти под этой учётной записью нельзя.

## Локальный запуск

```
npm install
copy .env.example .env
npm run dev
```

Тесты используют временную базу и не трогают `data/rentproof.sqlite`.

## Почему не PostgreSQL прямо сейчас

Схема написана на переносимом SQL: явные внешние ключи, индексы и временные поля. Переключение на пустой PostgreSQL без переноса данных остановит уже созданные аккаунты, поэтому production остаётся на SQLite с постоянным диском.

Чтобы перейти позже:

1. Поднимите PostgreSQL и сделайте дамп SQLite (`sqlite3 .dump` с поправкой типов `INTEGER`/`TEXT` и булевых `0`/`1`).
2. Замените `node:sqlite` в `src/lib/db.ts` на драйвер с теми же подготовленными запросами.
3. Прогоните `npm test` на копии, а не на единственном файле пользователей.
4. Храните строку подключения только в секрете хостинга.

На хостинге без постоянного диска SQLite использовать нельзя: файл пропадёт при перезапуске. Для такого хостинга сначала нужен внешний PostgreSQL или libSQL и отдельная проверка миграции.
